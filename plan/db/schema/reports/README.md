# Reports Schema

This folder captures the schema and metadata used for final report generation and artifact tracking.

## Scope
The report schema keeps only the sanitized, finalized metadata required for:

- reporting
- timeline views
- summary analysis
- retention control
- integrity validation
- evidence references

## Included objects
- `reports`
- `report_findings`
- `report_artifacts` (optional, if separate artifact metadata is needed)

## Design Rule
Report data must not contain raw sensitive payloads or fully detailed exploit code.

## Typical fields
- report id
- scan run id
- client id
- project id
- generated by
- score
- status
- summary
- report URI
- hash
- retention date
